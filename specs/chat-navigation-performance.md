# 聊天导航增量投影

## 目标与证据

`ConversationTimeline` 已通过 `createConversationTurnRenderer` 保持未变化历史回合的对象引用；
`ConversationTurnNavigator` 在 `renderUnits` 变化后仍对全部回合重建摘要。
本轮减少流式回复期间的历史摘要计算与目录对象分配，不改变目录功能和视觉规则。

## 所有权与边界

- 会话事实仍由原有运行时与会话投影负责；目录只是 UI 派生数据。
- 每个导航组件持有独立投影器，弱引用缓存不可变回合，卸载后释放。
- 相同回合引用、位置和摘要配置复用目录项；语言、摘要限制、位置或回合变化时重新计算。
- 历史前插必须更新 `unitIndex`，不能以复用为由跳到旧位置。
- 不按 turn ID 跨会话复用，不增加持久化、协议或业务状态；Desktop continuous 和 Web replayable 仍消费各自已有投影。
- 无迁移；错误沿用原计算路径，不吞异常。

```mermaid
flowchart LR
  A[运行时会话事实] --> B[现有不可变回合投影]
  B --> C[组件内目录投影器]
  C --> D[目录与导航展示]
  D --> E[现有跳转回调]
```

## 验收

1. 1000 回合持续更新末尾回复：历史目录项保持引用，输出与完整计算一致。
2. 历史插入、回退、同 ID 消息修正：位置与内容符合完整计算。
3. 切换语言和摘要长度、段落限制：无旧摘要泄漏。
4. 不同投影器相互隔离；隐藏回合与非用户输入保持既有语义。
5. 运行已有长会话与目录测试，以及仓库类型、Lint、架构检查；分别报告基线失败。

本轮不新增交互；浏览器验收应覆盖流式输出期间打开目录、跳转历史、前插历史后跳转，
以及移动端目录搜索。未实际执行时必须明确标注。
