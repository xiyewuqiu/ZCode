# 长会话优化验证记录

> 这是前一阶段的历史测量。后续已将工作项 `content-visibility` 替换为真正虚拟化；当前行为、规模与最终检查见 [最新验证记录](desktop-performance-iteration-results.md)。下文的 DOM 数与性能值只对应当时实现。

2026-10-01，本地 Windows 环境，合成数据。算法测试使用 Node 24.14.0；浏览器为 Chrome、Vite 开发模式。本记录不代表真实设备矩阵、生产构建或端到端 Agent 网络性能。

## 已落地

- shared 帧内归约：复用既有候选快照 accumulator，避免逐事件复制消息窗口。已发布快照不变，事件顺序不变。
- UI 按稳定 turnId 分组，按行引用验证投影缓存；只保留当前窗口的轮次。Timeline 缓存按 session/logEpoch 隔离。
- 计时更新只替换运行段耗时，复用 flow 与历史数组。工具输入转换使用 WeakMap，避免按 ID 永久缓存旧版本。
- 查找关闭时不读取正文；查找缓存从 turn key 改为投影对象引用，补页、同 ID 替换后重新索引。
- 大于等于 40 项的工作列表逐项使用 `content-visibility: auto` 与记忆高度，减少视口外布局和绘制；打印时恢复完整布局。

状态所有者仍为 CLI/runtime 与现有 ConversationProjectionStore。没有修改 admission、owner/lease、持久化、帧顺序校验、Desktop continuous 或 Web replayable 的恢复规则。

## 实测

| 场景                                              |                  对照 |                优化后 |
| ------------------------------------------------- | --------------------: | --------------------: |
| 20,000 行 / 256 条文本增量                        |       逐条归约 61.4ms |        帧内归约 1.6ms |
| 1000 轮 / 50 次尾部更新                           |      完整物化 371.0ms |       缓存物化 21.6ms |
| 1000 工作项、桌面滚动 + 20Hz 流式更新，帧间隔 P95 | 关闭内容可见性 23.9ms | 开启内容可见性 16.3ms |
| 同一场景，390×844 窄屏，帧间隔 P95                |            未采样对照 |                23.4ms |

浏览器每组统计 164 个预热后的帧间隔，桌面与窄屏都没有超过 50ms 的样本。桌面挂载 10 个轮次、1060 个行节点，全部数据为 1637 行。以上是单次本机测量，不设脆弱的绝对耗时断言。

两种视口均通过搜索早期问题、展开/收起、输入、回到底部、完成态转换和行数不变的浏览器断言。测试直接装配正式 ConversationTimeline；没有伪造 transport、Host 或真实 Agent 端到端通过结果。

## 回归与边界

- 10 个新增 Node 场景覆盖深冻结快照、所有流式路径、混合增量顺序、分支裁剪、缓存引用稳定、补页/修订/phase、guide 时钟与空搜索；另执行 6 个现有 UI 场景。
- 根类型检查、定向测试类型检查均通过；16 个 Node 测试通过。Lint 为 0 错误、63 条既有警告，修改文件的定向 Lint 为 0 警告。架构基线为 0，新违反为 0；改变模块为 shared 与 ui。
- 生产源码新增 219 行、删除 80 行，净增加 139 行；包括独立的行分组文件，不含测试与文档。
- 可复现命令见 `packages/ui/test/browser/README.md`。
- 窄屏 P95 仍超过 16.7ms，不能宣称所有场景稳定 60fps。首次物化与变化轮次仍有线性开销；内容可见性保留 DOM，不能保证无限历史的内存恒定。
- 未覆盖真实多年会话、单条超大工具输出、Electron 原生窗口以及 macOS/Linux/真实手机。全项目其他界面尚未完成性能审计。
